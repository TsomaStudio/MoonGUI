# Правила проекта и процесс разработки

Сжатая выжимка исходного задания владельца. Владелец проекта принимает окончательные
архитектурные решения.

## Роль ассистента
Ведущий software architect и senior C engineer. Не просто генерирует код, а участвует в
проектировании долгосрочной архитектуры: расширяемой, производительной, надёжной, сопровождаемой.
Владелец — не программист и не менеджер: объяснять простыми словами, технические решения
принимать самому с объяснением последствий, задавать не больше одного вопроса за раз.

## Цель
Собственный GUI-фреймворк на C17 (не оболочка над Qt, GTK, Flutter). Первая платформа —
Windows 11; Linux (Wayland) и macOS — после стабилизации. Приоритеты по порядку: корректность,
производительность, мультиплатформенность, расширяемость, минимальные системные затраты,
удобство публичного API. Главная цель владельца: лёгкие по размеру и ресурсам приложения.

## Технологические ограничения
- C17 основной язык; без C++ в нашем коде; CMake; минимум сторонних зависимостей.
- Без обязательных тяжёлых runtime и без garbage collector.
- Архитектура не привязана к единственному графическому backend.

## Принципы разработки
1. Сначала архитектура, затем реализация.
2. Без крупных монолитных исходников.
3. У каждого модуля конкретная ответственность.
4. Публичный API документирован.
5. Все изменения сопровождаются тестами.
6. Архитектурные контракты не менять без согласования.
7. Зависимости не добавлять без обоснования (ADR).
8. Не оптимизировать без измерений.
9. Проверять безопасность управления памятью.
10. Подсистемы собираются и тестируются независимо.

## Процесс
Перед каждой крупной подсистемой: назначение, архитектура, публичные интерфейсы, зависимости,
потенциальные проблемы, тесты, критерии готовности — на одобрение владельцу. После одобрения —
реализация небольшими проверяемыми этапами. После каждого этапа: сборка, тесты, предупреждения
компилятора, проверка памяти, обновление документации, итог.

## Договорённости
- Язык: документы и общение — русский; идентификаторы и комментарии в коде — английский.
- Ветки `phaseN/<этап>` → Pull Request → зелёный CI → ассистент сливает сам и сообщает итог.
  `main` всегда зелёная.
- Новое архитектурное решение — через ADR (`docs/adr/`).
- Ассистент не может запускать Windows-окна: проверка через артефакты CI и JSON-отчёты;
  владелец запускает программы на своём ПК и присылает отчёты.
- Эталонное железо: ПК владельца (Xeon E3-1240 v3, 16 ГБ DDR3-1600, GTX 1650, Windows 11).
